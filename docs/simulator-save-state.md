# Simulator save / restore

`PygamePacmanEnv` supports JSON checkpoints at completed `reset()` / `step()`
boundaries. `snapshot()` remains a gameplay summary; use `save_state()` for
continuation.

```python
import json
from pathlib import Path
from pacman_env.env import PygamePacmanEnv, PygamePacmanEnvConfig

config = PygamePacmanEnvConfig(
    pacman_python_root="/absolute/path/to/pacman-python",
    max_steps=512,
    ghost_mode="normal",
    episode_life_mode="original_three_lives",
)
with PygamePacmanEnv(config) as env:
    obs, info = env.reset(seed=7)
    obs, reward, terminated, truncated, info = env.step("L")
    saved = env.save_state()
    Path("state.json").write_text(json.dumps(saved), encoding="utf-8")
    # Same worker rollback:
    obs, info = env.restore_state(saved)

with PygamePacmanEnv(config) as env:
    # Original process may already have exited.
    saved = json.loads(Path("state.json").read_text(encoding="utf-8"))
    obs, info = env.reset(saved_state=saved)
    obs, reward, terminated, truncated, info = env.step("R")
```

## Saved contents

- Pacman, all six ghost objects (including vulnerable rendering sprites), fruit,
  game timers, lives, score and camera.
- Complete mutable level map, including exact pellet positions; pathfinder
  nodes, paths and search lists; event ledger and logic-frame counter.
- Python `random` state. This simulator uses that RNG, not NumPy randomness.
- Animation counters, mutable sprite pixels and exact framebuffer. Restore does
  not call `Draw()`, because drawing mutates animation and pellet blink timers.
- Wrapper step count, original seed, initial pellet count, death count and
  finished status. IPC request IDs and temporary worker directories are local
  transport details and are not restored.

The format is a versioned JSON object graph with preserved tuple keys and shared
references, compressed surface pixels, and a SHA-256 integrity checksum. It
does not use pickle. Treat it as an opaque artifact generated by `save_state()`;
editing fields is not a supported way to design a new maze.

## Compatibility and limits

- Restore requires matching simulator/environment source hashes, binary game
  resources (including the game-over font), ruleset, map, life mode, step budget,
  Python, pygame and SDL versions. Schema/source changes
  require new checkpoints; no migration is implemented.
- The original horizon is preserved. A save at step 100 of 512 has 412 steps
  left. A terminated/truncated save stays finished and rejects `step()`.
- `seed` and `saved_state` cannot be passed together. The saved RNG is restored
  directly, without replaying previous actions or reseeding the continuation.
- Supports this Level 1 simulator at public API boundaries, not arbitrary
  instruction-level pauses or a different maze/ruleset.
- Saves simulator state only. Planner memory, model sampling RNG, reward
  wrapper history, PPO optimizer state and trainer state are separate. Training
  from intermediate states still needs explicit reward/horizon semantics.
- High scores used by the game-over image are kept in the game object and saved;
  headless episodes do not write the shared `res/hiscore.txt` file or prompt for
  a player name. Sound playback, OS event queues and wall-clock time are not
  saved. The bridge uses a no-sleep clock and clears OS events on restore.
  No display or keyboard control is required.

## Deterministic sanity checks

```bash
python -m pytest tests/env/test_saved_state.py tests/env/test_saved_state_validation.py -v
```

Tests compare raw RGB hashes, complete transition info (including atomic
substeps/events), reward, done flags, and the complete saved object graph/RNG.
They cover JSON file round trips, a fresh process, repeated saves, both ghost
modes, multiple seeds, respawn, power pellets, terminal states, and corruption /
configuration rejection. Failed graph loads roll back the old game and RNG so
the running episode can still continue. A worker runtime directory is excluded from transition
comparison because it intentionally changes with the process.
